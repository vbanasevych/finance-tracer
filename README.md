# Фінансовий трекер (Finance Tracker)

**Лабораторний проєкт з дисципліни "Веб-технології"**

Веб-додаток для відстеження особистих фінансів. Платформа дозволяє користувачам вести облік доходів та витрат, керувати різними рахунками, встановлювати місячні ліміти (бюджети) на конкретні категорії та зручно зберігати фотографії чеків у хмарному сховищі.

## 🛠 Стек технологій
* **Backend:** Java, Spring Boot, Spring Data JPA
* **База даних:** PostgreSQL, Liquibase
* **Кешування:** Redis
* **Хмара та Інфраструктура:** AWS (EC2, S3), Docker, Docker Compose
* **CI/CD:** GitHub Actions, Docker Hub
* **Frontend:** Thymeleaf, Bootstrap 5, JavaScript (File API)
* **API та Тестування:** REST, OpenAPI (Swagger UI), Postman, JUnit 5, Mockito

На другому етапі додаток розширено повноцінним програмним інтерфейсом, оптимізовано роботу з даними та додано інструменти для аналітики й автоматизованого тестування.

* **Google Analytics:** Інтегровано скрипт `gtag.js` для відстеження поведінки користувачів на сторінках додатку.
* **Юніт-тестування:** Написано тести для всіх нових REST-контролерів та оновлено існуючі тести MVC-контролерів і сервісів, зберігши 100% покриття коду.

### Pull Request 3: Інфраструктура (Docker, Cloud, CI/CD) (✅ Виконано)
На третьому етапі було автоматизовано процес збірки та розгорнуто проєкт у хмарі.

**З файлу умов виконано наступні пункти: C2, C3, C3.**

**Що було зроблено:**
* **Контейнеризація:** Написано `Dockerfile` (Multi-stage build) для оптимізованої збірки Spring Boot додатку. Створено `docker-compose.yml` для об'єднання додатку, PostgreSQL та Redis у єдину Docker-мережу.
* **CI/CD Пайплайн:** Налаштовано автоматизацію через **GitHub Actions**. При злитті коду в гілку `mater` чи створенні pull request пайплайн збирає Docker-образ та публікує його на **Docker Hub** (авторизація налаштована через GitHub Secrets).
* **Cloud Розгортання:** Додаток успішно розгорнуто на віртуальному сервері **AWS EC2 (Ubuntu)**. Налаштовано production-версію `docker-compose.prod.yml`, яка стягує готовий образ із Docker Hub. Всі секрети захищені та винесені у файл `.env` безпосередньо на сервері. Процес розгортання задокументовано у файлі `AWS_DEPLOYMENT.md`.
